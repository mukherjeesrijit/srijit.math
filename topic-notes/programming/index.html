Programming

1. Python, C & pseudocode

  • Trace by hand: keep a table of the variables after each line or loop pass; for recursion, draw the call tree.
  • Lists: append(x) adds one element (even a list), extend(L) adds each element of L, insert(i, x) needs an index; slicing L[a:b] excludes b.
  • Mutability: a default argument like lst=[] is created once and shared by every call that omits it; a closure keeps its own copy of the variables of the call that made it.
  • Sets: A - B, A | B, A & B; tuple assignment A, B, C = ... evaluates the whole right side first.
  • Division: in Python 3, / gives a float and // an integer; % is the remainder.
  • Swapping: D[i], D[j] = D[j], D[i]; swapping the ends and moving inwards reverses a list.

2. Data structures

  • Stack (LIFO): push, pop. Queue (FIFO): enqueue, dequeue. Deque: insert and remove at both ends. All $O(1)$.
  • Hash tables: $O(1)$ average lookup. With open addressing and load factor $\alpha < 1$, an unsuccessful search or an insertion takes at most $\frac{1}{1 - \alpha}$ probes on average; with linear probing a collision moves to the next free slot.
  • Binary trees: $L \le I + 1$ (leaves, internal nodes); a tree of height $H$ has between $H + 1$ and $2^{H+1} - 1$ nodes.
  • Traversals: preorder (root, left, right), inorder (left, root, right), postorder (left, right, root). Inorder with preorder or postorder determines the tree; for a full binary tree preorder with postorder does too.
  • Heaps: a complete binary tree with parent $\le$ children; insert and extract-min in $O(\log n)$.
  • B$^+$ trees: a node with $n$ pointers holds $n - 1$ keys; an overflowing node splits and sends its middle key up.

3. Searching, sorting & complexity

  • Big-O: $O(1) < O(\log n) < O(n) < O(n\log n) < O(n^2) < O(2^n)$.
  • Binary search needs a sorted array (constant-time access): $T(n) = T(n/2) + 1$, $O(\log n)$; at most $\lfloor\log_2n\rfloor + 1$ comparisons.
  • Bubble sort: passes of adjacent swaps; the number of swaps equals the number of inversions. Insertion sort: one swap per inversion, $O(n)$ on nearly sorted input. Selection sort: puts the minimum in place each pass, at most $n - 1$ swaps.
  • Merge sort $O(n\log n)$ always. Quicksort: $O(n\log n)$ expected, $O(n^2)$ worst (e.g. sorted input with the first or last element as pivot); expected time $T(n) = \frac1n\sum_k[T(k) + T(n - 1 - k)] + O(n)$.
  • Lower bound: comparison sorting needs $\Omega(n\log n)$ comparisons.

4. Graph algorithms

  • Representations: adjacency lists ($O(V + E)$ space) or an adjacency matrix ($O(V^2)$).
  • BFS finds shortest paths in unweighted graphs; DFS explores as deep as possible first. Both run in $O(V + E)$ and reach exactly the vertices reachable from the start.
  • DFS edge types: tree, back, forward, cross; an undirected DFS has only tree and back edges, and a directed graph has a cycle iff DFS finds a back edge.
  • Topological sort of a DAG: an order where every edge goes forward (Kahn's algorithm or reverse DFS finishing order).
  • Shortest paths: Dijkstra for non-negative weights; a shortest path's subpaths are shortest, so an extra edge that would shorten it cannot exist.
  • Reversed graph: $u$ is reachable from $v$ in $G$ iff $v$ is reachable from $u$ in $G^R$.

5. Recursion, divide & conquer, greedy & DP

  • Recursion: a base case and a smaller call. The number of calls of $f(n) = f(n - 1) + f(n - 2)$ satisfies $c(n) = 1 + c(n - 1) + c(n - 2)$.
  • Master theorem: $T(n) = aT(n/b) + O(n^d)$ is $O(n^d)$, $O(n^d\log n)$ or $O(n^{\log_ba})$ as $d >, =, < \log_ba$.
  • Divide and conquer: split, solve the parts, combine (merge sort, binary search, fast exponentiation).
  • Greedy: take the best local choice; correct only with an exchange argument.
  • Dynamic programming: store answers to overlapping subproblems (memoisation or a table); e.g. Fibonacci in $O(n)$, edit distance, knapsack.

6. Databases & SQL

  • Keys: a superkey determines every attribute; a candidate key is a minimal superkey; a primary key is never NULL; a foreign key must match an existing key (or be NULL).
  • Functional dependencies: compute the closure $X^+$ to test keys and derived dependencies. BCNF: every non-trivial $X \to Y$ has $X$ a superkey. A decomposition that loses dependencies needs joins to check them.
  • Relational algebra: $\sigma$ (select rows), $\pi$ (project columns), $\bowtie$ (natural join on equal common attributes), $\cup, \cap, \setminus$, and division $R \div S$ (the $x$ paired with every $y$ in $S$).
  • SQL: SELECT ... FROM ... WHERE ... GROUP BY ... HAVING; a subquery can be compared with each row (correlated). GROUP BY CUBE(A, B) groups by every subset of $\{A, B\}$.
  • Indexes: hash indexes serve equality; B$^+$ trees serve equality and ranges.
  • ER to relations: one relation per entity, one per many-to-many relationship, one per multi-valued attribute.
  • OLAP: roll-up goes to coarser levels, drill-down to finer ones; with hierarchies of $L_i$ levels there are $\prod(L_i + 1)$ cuboids.
